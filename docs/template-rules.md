# 模板规则、来源与待确认事项

## 原始文件状态

本次用户附件只有需求文本，没有 XLSX。未读取真实模板，未确认 Remarks 或批注的具体内容。需求中描述的长度冲突、乱码、示例电话、国家表异常均作为待核实事项记录，不能将描述当作实际文件检测结果。

`python -m app.cli inspect-template` 可在原模板到位后打印：工作表名称／顺序、33 个实际表头、批注、字体颜色、数据校验范围和公式，以及 Data table / Remarks 原始单元格内容。此命令只读模板；输出可能包含模板示例值，应在本地审阅。

## 规则及依据

| 规则 | 当前实现 | 来源与确认状态 |
| --- | --- | --- |
| 工作表和表头 | 三表顺序严格匹配，A:AG 33 列逐字匹配 | 用户需求；待真实文件核验 |
| 必填字段 | OrderID、ReceiverName、ReceiverCountry、ReceiverAddress1、ReceiverCity、ReceiverState/Province、ReceiverZipCode、ReceiverPhone、ShippingDate、Weight、ItemName、Weight Unit(Default:bls) | 用户给出的红色必填清单；未检查真实字体颜色 |
| OrderID 字符 | ASCII 字母／数字／下划线／连字符 | 本地保守策略，不是已确认平台限制 |
| OrderID 长度 | 默认最多 30 个字符，可配置 | 本地保守策略；用户指出 Remarks 与批注可能不一致，具体文本未知 |
| 地址长度 | 四个地址字段各最多 35 个字符，可配置 | 本地保守策略，不声称对应平台真实上限 |
| 其他文本 | 不静默截断；非法 XML 控制字符、超过 Excel 单元格长度阻断 | XLSX 写入安全边界；平台的其他长度／字符规则未确认，每单返回警告 |
| 手机／邮编 | 文本且非空，不套统一数字正则 | 用户要求；国际格式允许符号和前导零 |
| 国家／地区 | US 模拟地址使用 MA；非 US 警告人工核对 | 不把 Data table 不加检查地转为全球字典 |
| 原产国／商品重量 | 缺失阻断，不推测填充 | 本地业务完整性策略，区别于红色表头必填项 |
| 单位 | kg/cm、lbs/in、oz/in | 用户明确枚举；不自动转换，不改标签冒充数值换算 |
| 用途 | Commercial、Sample、Personal Use、GIFT；可空 | 用户给出枚举；未列红色必填则允许空 |
| 保险 | Y、N 或空 | 用户明确枚举 |
| 危险品 | 空、BATTERY_MARKED、BATTERY_UNMARKED | 用户明确枚举；只复制明确来源，不自动判断 |
| 日期 | yyyy/MM/dd | 用户要求；从包裹日期输出 |
| 金额 | USD，买家运费、商品单价和保险值非负 | 用户要求及本地一致性校验；不替换币种标签 |
| 重量／尺寸 | 重量必须有且 >0；填写的尺寸 >0 | 用户要求 |
| 多行结构 | 默认阻断多商品或多包裹 | 实际解析规则未获样本证实 |
| EEI/FTR/内部 id/物流单号 | 不输出到模板 | 模板没有对应列 |

表头 `Weight Unit(Default:bls)` 保留 `bls` 原文。保守限制的配置不会静默截断任何业务值；放宽配置意味着需要重新验证真实平台限制。XLSX 本身的最大文本长度仍是硬限制。

## 多商品、多包裹策略扩展

1. 收集无真实个人信息的已成功导入样本：至少多商品单包裹、单商品多包裹、多商品多包裹，以及异常／退回样本。
2. 对照实际模板版本，记录每一续行的 OrderID、地址、运费、重量、尺寸、商品列哪些重复、哪些为空。确认包裹边界与数量规则，不能仅凭生成文件成功推断。
3. 在 `app/services/export.py` 中新增策略类并增加显式策略选择；继续从 `ShipmentItem` 读取分配，不遍历订单商品与包裹形成笛卡尔积。
4. 单包裹可沿用平台订单号；多包裹必须用数据库中已保存的稳定 `package_reference`。查询中的 shipment.order_id 保留平台订单映射，不临时生成编号。
5. 确认订单买家运费在多包裹中的表达方式。当前没有分摊算法，不能默认对每个包裹重复收费或平均分配。
6. 增加原始模板只读性、样式／批注／验证、行数、每商品数量、跨包裹不重复、金额不重复、稳定编号、真实样本往返测试。
7. 在真实 PostPony 测试导入完成后记录模板文件哈希、平台版本／验证日期、输入与平台结果；只有此时才说明该特定布局通过实际导入。

多策略不应修改查询业务。未来 provider 返回相同的规范字段结构，字段映射放在 provider 适配层；同步仍保护本地备注和人工物流数据。真实来源的 is_mock 必须显式为 false，并使用独立 source 命名；当前路由只调用 MockDataProvider。
